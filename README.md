# Lunaris 1.2.1

Автокликер для Windows x64 с интерфейсом в стиле macOS. Запускается из Lunaris.exe, установка не нужна. Нужен .NET Framework 4.8 (есть в Windows 11 и актуальных Windows 10).

## Использование

1. Выбери ЛКМ или ПКМ. Она будет и кнопкой удержания, и кнопкой генерируемых кликов.
2. Установи «От» и «До» — от 1 до 60 CPS. Число можно ввести вручную и нажать Enter либо передвинуть ползунок.
3. Нажми F6 (первоначальный бинд) или переключатель в окне. Режим включится.
4. В нужном окне зажми выбранную кнопку мыши. Кликер работает только во время удержания. Отпускание прекращает автоклики, но режим остаётся включённым.
5. Повторное нажатие того же бинда отключает режим: одна клавиша и для включения, и для выключения.

«Включить / выключить» позволяет записать букву, цифру, F-клавишу или сочетание с Ctrl, Alt, Shift. Esc отменяет запись. F12 — системная клавиша и не принимается. Если бинд занят другим приложением, появится сообщение; переключатель продолжит работать.

Скорость случайно выбирается между заданными CPS для каждого интервала. Одинаковые границы дают постоянную целевую скорость. Реальная скорость зависит от планировщика Windows и приложения, которое принимает клики. Слишком низкая или высокая граница ограничивается диапазоном 1–60, пересечение границ автоматически исправляется.

В собственном окне настроек автоклики приостановлены. Кнопка «Тест кликов» открывает отдельную площадку со счётчиком. Нажми бинд и удерживай выбранную кнопку на площадке; обычные ручные клики тоже учитываются. Закрытие площадки отключает режим.

Настройки сохраняются в `%LOCALAPPDATA%\MellowClick\settings.xml`. При запуске режим всегда выключен. При блокировке сеанса или переходе в сон режим отключается. Красный кружок закрывает приложение, жёлтый сворачивает, зелёный переключает «поверх всех окон».

## Новое в 1.1

В версии 1.1.1 включение и выключение выполняются одним настраиваемым биндом (по умолчанию F6). Отдельная клавиша остановки удалена. Скрытие и возврат окна также используют один бинд (по умолчанию F10), независимый от режима автоклика.

**Скрытие окна.** F10 по умолчанию скрывает окно с панели задач и из Alt+Tab; повторное нажатие возвращает его. Режим автоклика и отслеживание удержания продолжают работать. Бинд меняется в строке «Скрыть / вернуть окно»; Ctrl, Alt и Shift поддерживаются. Бинд скрытия и бинд включения должны различаться. Если сочетание занято, приложение предлагает выбрать другое и не скрывается без доступного бинда возврата. Повторный запуск того же .exe также возвращает существующее окно. Процесс остаётся виден в диспетчере задач.

**Чёрная тема.** Кнопка ☀ / ☾ в верхней части окна переключает светлый и тёмный интерфейс. Выбранная тема подсвечивается и применяется также к тестовой площадке.

**Работать в приложении.** Флажок слева ограничивает автоклики активным окном указанного процесса. По умолчанию включён, имя — `Minecraft.Windows.exe`. Можно ввести имя другого .exe (регистр не важен), затем нажать Enter или перейти в другое поле. Имя без .exe дополняется автоматически. Если передать путь, используется только имя файла. При переключении в другое окно клики приостанавливаются; возврат в нужное окно разрешает их снова при удержании кнопки. Пустые и некорректные имена не разрешают клики при включённом ограничении. Снятие флажка разрешает работу в любых приложениях. Тестовая площадка кликера является отдельным исключением, чтобы можно было проверить клики без изменения выбранного процесса.

Тема, имя процесса, флажок и оба бинда сохраняются. Настройки версии 1.0 подхватываются автоматически.

## Исправления в 1.2

Нажатие и отпускание больше не отправляются мгновенно в одном пакете. Между состояниями есть короткие интервалы, зависящие от CPS: сначала отпускание, затем нажатие и обязательное отпускание. Отпускание физической кнопки, выключение бинда и потеря целевого окна отменяют ожидание; после начатого нажатия всегда отправляется отпускание. При выходе приложение ждёт завершения текущего нажатия.

Удержание также отслеживается стандартным Windows Raw Input в фоновом режиме. Собственные синтетические события не активируют и не сбрасывают физическое удержание. Фильтр целевого приложения учитывает захват мыши игровым окном.

При запуске новая версия пытается корректно закрыть старый экземпляр Lunaris или Mellow Click из того же сеанса Windows. Если старое окно не закрывается, появится сообщение с номером версии. Новый запуск больше не должен незаметно возвращать старую сборку. Повторный запуск той же версии по-прежнему возвращает её окно.

Под именем приложения отображаются последняя проверенная цель и количество отправленных кликов. Это счётчик отправки в Windows, а не подтверждение получения кликов игрой. Если игра не реагирует, проверь выбранную кнопку, бинд, имя процесса и изменение счётчика. Если счётчик растёт, но реакции нет, приложение может фильтровать синтетический ввод.

## Совместимость

Клики отправляются стандартным Windows API [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput). Приложения с более высоким уровнем прав или игры, фильтрующие синтетический ввод, могут их не принимать. Совместимость с конкретной игрой не проверялась. Драйверов, внедрения в игру и обхода античита нет.

## Сборка из исходников

Запусти `powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1` из каталога исходников. Результат появится в `build\Lunaris.exe`. Используется штатный компилятор .NET Framework Windows x64, внешних пакетов нет.

Проверки: `Lunaris.exe --self-test C:\path\test-results.txt`. Процесс возвращает 0 при успехе. Самопроверка покрывает условия запуска/остановки, выбор кнопки, фильтрацию внедрённых событий, диапазон CPS, ошибки ввода, системный хук и регистрацию горячей клавиши. Для проверки настоящего SendInput выполняется пара противоположных минимальных движений указателя; кнопки мыши тест не нажимает.

`--self-test-passive` выполняет те же проверки без отправки событий мыши; тест SendInput отмечается как пропущенный. Добавлены проверки точного сопоставления процессов, обработки имён приложений, переключения палитр и контраста полей тёмной темы.
